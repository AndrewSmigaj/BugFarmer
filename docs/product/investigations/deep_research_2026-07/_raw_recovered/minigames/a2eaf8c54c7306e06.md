## 1. `CraftStationState` struct — definition, fields, creation, mutation

**Defined:** `/mnt/c/Users/emily/BugFarmer/nakama/modules/world/craft_stations.go:20-30`

```go
// CraftStationState is the runtime state of a recipe processor (furnace/anvil/workbench…). It is
// a Container (the Output grid) plus the active recipe + a process queue. Lazily created the first
// time a player opens the station. Outputs are display/inventory state — NEVER in the sim hash.
type CraftStationState struct {
	Key      string // CraftStationKey(gx,gy)
	EntityID string // occupant entity id (recipe lookups)
	GridX    int    // anchor cell
	GridY    int    // anchor cell

	Output   []InventorySlot // the output grid (collect from here)
	Recipe   string          // active recipe id ("" = none selected)
	Queue    int             // batches remaining to produce (incl the one in progress)
	Progress int             // ticks into the current batch
}
```

Output grid size is a code constant, `craftOutputSlots = 8` (`craft_stations.go:15`). ```go

## 2. `processCraftStations` — the tick processing loop

`/mnt/c/Users/emily/BugFarmer/nakama/modules/world/craft_stations.go:338-376`

```go
func (m *Match) processCraftStations(state *WorldState, dispatcher runtime.MatchDispatcher) {
	for _, s := range state.CraftStations {
		if s.Queue <= 0 {
			s.Progress = 0
			continue
		}
		r := state.Recipes[s.Recipe]
		if r == nil {
			s.Queue = 0
			s.Progress = 0
			continue
		}
		total := r.ProcessTicks
		if total < 1 {
			total = 1
		}

		if s.Progress < total {
			s.Progress++
		}
		if s.Progress < total {
			// Periodic progress echo ... (client interpolates between these)
			if s.Progress%20 == 0 {
				m.broadcastCraftStationUpdate(dispatcher, state, s)
			}
			continue
		}

		// Batch complete — produce if there's room, else hold and wait for a collect.
		if !outputHasRoom(s, r.Output.Item) {
			continue // Progress stays at `total`; retry next tick
		}
		s.Progress = 0
		s.Queue--
		addOutput(s, r.Output.Item, r.Output.Count)
		m.broadcastCraftStationUpdate(dispatcher, state, s)
	}
}
```

Key mechanics for the refactor:
- One recipe (`s.Recipe`), one progress counter, one queue counter per station. The `Procs []CraftProcessor` refactor turns this outer body into an inner loop over `s.Procs`.
- **Progress ticks:** `s.Progress++` per tick until `total = r.ProcessTicks`.
- **Payout:** on completion, `addOutput(s, r.Output.Item, r.Output.Count)` merges into `s.Output` (`addOutput`, lines 173-186: existing stack else first empty cell).
- **Queue decrement:** `s.Queue--` only after a successful payout.
- **Output full:** `if !outputHasRoom(...) { continue }` — progress **stalls at `total`**, queue does not decrement, nothing is lost (inputs were consumed at queue time). With Procs[], "room" checking becomes per-proc against a shared output grid — a design question (do procs share one output grid, or one per proc?).

Inputs are consumed up-front at queue time, not here — see §3 `craftQueue`.

```go
func (m *Match) craftQueue(..., s *CraftStationState, recipeID string, qty int) bool {
	if recipeID == "" { recipeID = s.Recipe }
	r := state.Recipes[recipeID]
	if r == nil || r.Station != s.EntityID {
		m.sendWorldError(..., "That recipe isn't made here"); return false
	}
	if !recipeKnown(player, recipeID, r) {
		m.sendWorldError(..., "You haven't learned that recipe yet"); return false
	}
	if s.Queue > 0 && s.Recipe != recipeID {
		m.sendWorldError(..., "Finish or collect the current batch first"); return false
	}
	s.Recipe = recipeID
	if qty <= 0 { qty = 1 }
	queued := 0
	for b := 0; b < qty; b++ {
		if !playerHasInputs(player, r) { break }
		consumeInputs(player, r)   // inputs pulled UP-FRONT, Terraria-style
		s.Queue++
		queued++
	}
	if queued == 0 {
		m.sendWorldError(..., "Not enough materials"); return false
	}
	return true
}
```

### Summary of flags against the design sketch
1. **`campfire`/`stove` have no recipes** and are not currently functional craft stations — the sketch's marquee example can't be exercised until cooking recipes exist. Verify scope with the user.
2. **`interaction_type:"craft"` is not the recognition mechanism** (it's `RecipesByStation` membership); the sketch's "`craft_slots` int on the station entity" belongs in `WorldData`, but `resolveCraftStation` must be taught to read it (it reads no `WorldData` today).
3. **Output-grid model** assumes one item type (`craftOutputSlots=8`, `addOutput` single-stack merge). N parallel procs produce N item types into a shared 8-cell grid — decide shared-vs-per-proc output grids; may need to enlarge/partition `Output`.
4. **Legacy migration** is mandatory: whole `CraftStationState` is JSON-persisted, so shipped saves carry flat `recipe/queue/progress` that must fold into `Procs[0]` (§5).
5. **No existing craft-loop tests** — add them alongside the refactor (§8).
