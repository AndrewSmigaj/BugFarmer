## Q1 — TileDatabase.GetGroundTile / tile creation

`Assets/Scripts/World/TileDatabase.cs`

- `GetGroundTile(tileId)` (`:45-73`): returns fallback for null/empty (`:47-48`), lazily inits `_tileCache` (`:50-51`), returns cached tile if present (`:53-54`), else loads the texture and builds a tile.
- Tile creation (`:56-68`) — this is the load-bearing code:
  ```csharp
  var tex = Resources.Load<Texture2D>($"Tiles/{tileId}");   // :56  loads Texture2D, NOT a Sprite
  var sprite = Sprite.Create(tex,
      new Rect(0, 0, tex.width, tex.height),
      new Vector2(0.5f, 0.5f),
      tex.width);                                            // :60-63  PPU = texture width
  var tile = ScriptableObject.CreateInstance<Tile>();        // :64
  tile.sprite = sprite;                                      // :65
  tile.color = Color.white;                                  // :66
  _tileCache[tileId] = tile;                                 // :67
  ```
- Yes: runtime `Sprite.Create` from `Resources/Tiles/{id}` (loaded as `Texture2D`, so the PNG's own importer sprite settings are bypassed — see Q4). PPU is set to `tex.width`, so any square PNG becomes exactly 1 world unit regardless of source resolution.
- Material: the created `Tile` sets **no material** — only `sprite` and `color`. Tiles inherit the material from the `TilemapRenderer` (set at runtime, see Q3/Q5).
- Caching: `_tileCache` `Dictionary<string, TileBase>` (`:24`), keyed by tileId, populated at `:67`, read at `:53`. It is **never invalidated or cleared** — one `Tile` instance per id lives for the ScriptableObject's lifetime. Fallback tile cached separately in `_fallbackTile` (`:75-90`).
- `TileDatabase.Instance` is a singleton loaded from `Resources/TileDatabase` (`:27-39`).

## Q3 — SetGroundTile lifecycle / every write to groundTilemap

`TilemapManager.cs`. The tilemap is written in exactly **two** places (`groundTilemap.SetTile`):

- **Clear:** `UnloadChunk` `:961-994` → `groundTilemap.SetTile(..., null)` at `:975` for every cell in the chunk.

Call graph:
- `SetGroundTile` is called from:
  - `RenderChunk:778` (full 32×32 render on chunk load), and `RenderChunk` itself is called from `HandleChunkData` at `:430` (after `_loadedChunks[chunkPos] = chunk` at `:428`).
  - `HandleWorldUpdate:448` (single-cell live ground change from server op, when the `ground` field is present).
- `UnloadChunk` (the only tile-clearing path) is called from:
  - `UpdateChunkSubscriptions:195` — when a chunk leaves view distance (server unsub), and
  - `UnloadAllChunks:949` — cross-zone swap (`:945-959`), which loops every subscribed+loaded chunk.
- Material assignment: **once** in `Start()` `:96-97` → `LitMaterials.Apply(groundTilemap.GetComponent<Renderer>())`.

So sync is: server streams chunk payloads → `RenderChunk`/`SetGroundTile` paints; leaving view or zone swap → `UnloadChunk` paints `null`. There is no per-tile removal outside chunk unload; live edits go through `SetGroundTile` overwriting the cell.

1. Adding a second tilemap means adding a new child under `Grid` (`&323588080`) — currently `GroundTilemap` is its only child — and wiring a new serialized `Tilemap` field on `TilemapManager` (mirroring `groundTilemap` at `TilemapManager.cs:20`). Cell coords are 1:1 with the ground tilemap.
