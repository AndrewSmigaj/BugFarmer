## OVERLAPS to flag (one file/command → multiple governing skills)

1. **`tools/zonegen/scenes/zone_*.py` → zone-craft AND author-zone.** Editing a real-zone scene implicates both: zone-craft governs WHAT/whether-it's-interesting (its hard gate blocks writing `zone_*.py` before brief+options), author-zone governs the HOW (builder API, lint, previews). A hook on this glob should surface both. `scene_*.py` vignettes lean author-zone but zone-craft's landmark-scene gate also claims them.

2. **`tools/ecology/run_config.py` → ecology-tuning AND perf-tuning AND test-changes.** The identical command means three different disciplines (balance / profiling / determinism verify). The existing GATES maps it ONLY to test-changes, so the ecology-tuning HARD RULES (one-run-at-a-time, it restarts+snapshots nakama) and perf's dashboard reading are NOT enforced by the current gate. Highest-value multi-skill overlap.

3. **`docker compose build|up|restart` → run-backend AND test-changes.** In GATES under test-changes only; but these are run-backend's core lifecycle commands (and test-changes §3 also rebuilds the plugin). run-backend's "never rebuild while playing" gotcha is not surfaced when the command clears under test-changes.

4. **`nakama/data/entities/**` → economy AND add-object (and frontier-sync edge).** `recipes.json`/`crops.json`/shop fields lean economy; a new `placeables/occupants/items` row for a fresh object leans add-object. Sim-hash-bearing fields on an entity (per the deep-investigate triage: `movement_style`, `flies_over_fences`) make even a data edit a frontier-sync/determinism change.

5. **`tools/art/catalog/**` + `tools/sprites/gen_sprites.py` → add-object AND regenerate-sprite.** New asset (add-object: also edits entity JSON + publish + pixelclean) vs. redo existing (regenerate-sprite: `gen_sprites --force`, one pass, no publish). The `--force` flag is the only reliable command-level discriminator; the catalog dir alone can't tell them apart.

6. **`nakama/modules/world/**` → frontier-sync AND bug-spawning AND perf-tuning (and deep-investigate reads).** Spawn/persistence files (`handlers_bugs.go`,`match.go`,`zone_persist.go`,`ecology_director.go`) → bug-spawning; ledger/sim-read files (`messages.go`, influence/predation/food) → frontier-sync; `profiler.go`/hot loops → perf-tuning. A single-slug file gate on the whole dir would mis-route; needs file-level granularity.

7. **`nakama/data/species.json` → ecology-tuning AND frontier-sync.** Balance values (reproduce/feed/vision) are ecology-tuning; hash-bearing behavior fields (`movement_style`, `flies_over_fences`, predation geometry) are a determinism change → frontier-sync + the sync gates.

8. **`nakama/data/zones/**/zone.json` → bug-spawning AND ecology-tuning AND author-zone.** The `bug_spawning`/`ephemeral_swarms` block → bug-spawning; `species_caps`/Director bands → ecology-tuning; the file is also written by author-zone's `save()`.

9. **`tools/make_scene.py` / preview renders → add-object AND regenerate-sprite AND author-zone** (all use it as the "look at the PNG" step).
