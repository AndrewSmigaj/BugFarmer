## GRASS / TILE RENDERING

**Q1 — Can a taller-than-cell tile sprite overhang? Geometrically YES, but layering is the catch.**

- `TileDatabase.GetGroundTile` (`Assets/Scripts/World/TileDatabase.cs:60-63`) builds the sprite with `Rect(0,0,tex.width,tex.height)`, pivot `(0.5,0.5)` **center**, and `PPU = tex.width`. So a 16×24 PNG becomes a sprite **1.0 world-units wide × 1.5 tall**, centered on the cell.
- A Unity `Tilemap` does **not** clip a tile sprite to its cell — the sprite mesh draws at full size. With the center pivot + the ground Tilemap's `m_TileAnchor {0.5,0.5}` (`Scenes/SampleScene.unity:456`) and `Grid m_CellSize {1,1}` (`:658-659`), a 1.5-tall sprite overhangs **0.25 cell above AND 0.25 below** — symmetric, not "blades up only." To make blades stick up only you'd need a bottom-biased pivot in `Sprite.Create` (currently hard-coded center) or a shifted `tileAnchor`; there is no per-tile pivot data path today.
- **Load-bearing caveat — sorting.** The ground `TilemapRenderer` is in **Chunk mode** (`SampleScene.unity:434 m_Mode: 0`) with `m_ChunkSize 32×32` (`:429`) and `m_SortOrder: 0` (`:433`), on sorting layer **Ground / order 0** (`:426-428`, `m_SortingLayer: 1`; the runtime water overlay comment at `TilemapManager.cs:840-841` confirms "Ground" order 0). In Chunk mode every tile in a 32×32 chunk is batched into **one mesh at one sort order** — individual tiles cannot be depth-sorted against each other, so a grass tile overhanging the tile above it draws in fixed geometric mesh order (governed by `m_SortOrder`), not "front cell over back cell." Clean per-tile overlap layering would require switching the renderer to **Individual mode** (`m_Mode: 1`) with a Transparency Sort. Nothing in `TilemapManager.cs` sets anchor/mode/sort at runtime — it uses the serialized scene values; it only `SetTile`s into `groundTilemap` (`:880`) and, for water, copies `tileAnchor` onto the overlay (`:833`).
- Occupant sprites (real trees/grass tufts) render on a **separate** "Occupants" sorting layer with Y-sort `sortingOrder = -cellPos.y` (`TilemapManager.cs:971-973`), so tall *occupants* overlap correctly — only tall *tiles* hit the Chunk-mode limitation.
