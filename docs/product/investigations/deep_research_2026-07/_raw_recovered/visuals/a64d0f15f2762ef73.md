## How ground ids are read (the choke points)

Every server read of a ground tile id goes through `chunk.GetGroundTile(lx,ly)` or direct `chunk.Ground[ly][lx]` (zone.go:262, 266). Every client read goes through `TilemapManager.GetGroundAt()` or `chunk.Ground[ly][lx]`. There are exactly two "property registries": the server `state.TileDefs` map (`map[string]*TileDefinition`, keyed by exact id, loaded from `data/tiles.json`) and a set of hardcoded string comparisons. A composite `grass~dirt~diagNE` id fails every exact-key map lookup and every `==` literal.

Two independent, non-negotiable facts that shrink the blast radius:
- **Player speed is NOT derived from ground.** `TileDefinition.MovementMult` (tiles.go:15) is loaded and defaulted but has **zero consumers** in movement logic. `TileDefinition.IsWalkable()` (tiles.go:70) and `TileDefinition.CanPlaceOccupant()` (tiles.go:75) are **dead code — no callers anywhere** (confirmed grep, including tests).
- **Bug movement is NOT derived from ground id on the client.** `IsCellBlockedForBugs` (TilemapManager.cs:1412) reads only the server-pushed `_blocksBugsZoneWide` set; and the server's `BlocksBugsCells()` (state.go:706) scans **occupants only**, never ground tiles. So ground-based bug blocking exists only in the server sim path below.
