### Scroll wheel scheme (the confusing part)
NOT in ToolUseController or PlayerInputRouter — it lives in the debug self-bootstrapping `ShapedGroundSpike.cs:22-40`. Reads `Input.GetAxis("Mouse ScrollWheel")` only while a shovel is equipped:

## 2. The `_holdLatchedToBreaking` latch pattern (to mirror for Shift+LMB dig)

Field declared `PlayerInputRouter.cs:43`: `private bool _holdLatchedToBreaking;`

**Latch set** in `LatchBreaking()`, `PlayerInputRouter.cs:220-225` (called from the LEFT-click default/grab fallthrough at line 144):
```
private void LatchBreaking() {
    if (_breaking == null) return;
    _holdLatchedToBreaking = true;
    _breaking.HoldBreak();
}
```

**Repeat loop + release** at the top of `Update()`, `PlayerInputRouter.cs:65-77` — while latched it runs the held path every frame and swallows all other routing (early `return`), releasing on button-up:
```
if (_holdLatchedToBreaking) {
    if (Input.GetMouseButton(0)) { _breaking?.HoldBreak(); }
    else { _breaking?.StopBreaking(); _holdLatchedToBreaking = false; }
    return;
}
```

**Cadence lives inside the held handler,** not the latch. `BreakingController.HoldBreak()` self-throttles: `breakClickInterval = 0.25f` (`BreakingController.cs:19`), widened to `0.36f` for axe/pickaxe (`cs:66`). It only sends when `Time.time - _lastBreakTime >= cadence` (`cs:133-138`), resetting `_lastBreakTime=0` on a new target cell for an instant first hit (`cs:124-127`). The repeated send is `SendBreakRequest(anchorCell)` → `TileBreakMessage{grid_x,grid_y}` at `OpCodes.TileBreak = 6` (`cs:200-217`). `StopBreaking()` clears `_isBreaking`/`_breakingCell` (`cs:193-198`).

To mirror for Shift+LMB "hold to dig": add a parallel `_holdLatchedToDigging` bool + a `ToolUseController.HoldDig()` that self-throttles on the shovel cooldown and repeats `SendToolUse(cell, null, true)`, gated by the latch block in `Update()`.

## 3. Block-breaking crack pipeline (reuse for ground dig)

### Crack overlay component — CELL-KEYED (works on any ground cell)
`BreakingVisual.cs` — a plain `SpriteRenderer` overlay on `sortingLayerName = "Occupants"`, `sortingOrder = 1000`, alpha 0.9 (`Awake`, lines 25-37). `SetProgress(float 0..1)` picks the stage: `damagePercent = 1 - progress`, `stageIndex = Floor(damagePercent * length)` clamped, from the shared `_breakStages[]` (`SetProgress`, lines 42-69). Stages are the 4 sprites loaded once via `EntityDatabase.GetBreakStageSprites()` → `Resources.Load<Sprite>($"Effects/break_stage_{i+1}")` for i=0..3 (`EntityDatabase.cs:246-250`), pushed in with `BreakingVisual.SetBreakStages(...)` (`TilemapManager.cs:151-154`).

**The key is a world cell, NOT an occupant/entity.** In `TilemapManager.cs:99`:
```
private Dictionary<Vector2Int, BreakingVisual> _breakingVisuals = new Dictionary<Vector2Int, BreakingVisual>();
```
Keyed by `Vector2Int` cell coords → so it already works on a bare ground cell; nothing ties it to an occupant. The overlay GameObject is positioned by `CellToWorld(cellPos)` (cell center) and parented to `occupantContainer` (`ShowBreakingProgress`, `cs:1195-1211`):
```
if (!_breakingVisuals.TryGetValue(cellPos, out var visual)) {
    var go = new GameObject($"Breaking_{cellPos.x}_{cellPos.y}");
    Vector3 pos = CellToWorld(cellPos);
    go.transform.position = pos;
    go.transform.SetParent(occupantContainer);
    visual = go.AddComponent<BreakingVisual>();
    _breakingVisuals[cellPos] = visual;
}
float progress = (float)currentHP / maxHP;
visual.SetProgress(progress);
```
Teardown: `RemoveBreakingVisual(cellPos)` destroys the GO and drops the dict entry (`cs:1213-1223`); also called on completion, chunk unload, and world updates (`cs:595,611,634,681,1182`).

### BreakProgress receive path
OpCode `BreakProgress = 45` (`WorldMessages.cs:13`). Struct `BreakProgressMessage` — `WorldMessages.cs:97-104`. Fields: `int grid_x`, `int grid_y`, `int current_hp`, `int max_hp`, `string player_id`.

Dispatch: `HandleMatchData` switch `case OpCodes.BreakProgress: HandleBreakProgress(state);` (`TilemapManager.cs:291-292`). Handler `HandleBreakProgress`, `cs:663-688`:
```
var msg = JsonUtility.FromJson<BreakProgressMessage>(json);
var cellPos = new Vector2Int(msg.grid_x, msg.grid_y);
if (msg.current_hp <= 0) RemoveBreakingVisual(cellPos);
else                     ShowBreakingProgress(cellPos, msg.current_hp, msg.max_hp);
```

**To reuse for ground dig:** the server just needs to emit `BreakProgress` messages (OpCode 45) keyed at the dug ground cell's `grid_x/grid_y` with `current_hp`/`max_hp` reflecting dig stages; the client crack pipeline is already cell-keyed and will render the 4-stage overlay on that ground cell with zero client changes. `current_hp <= 0` clears it.

## 4. Shovel selection state + GroundID grammar

State stored in `ShovelSelection.cs` (static class):
- `Materials[]` palette (`cs:12-15`): grass, dirt, sand, mud, stone_floor, stone_path, wood_floor, cave_floor (mirrors server `tiles.go shovelMaterials`).
- `MatAIndex` (default 0/grass), `MatBIndex` (default 1/dirt), `ShapeIndex` (default 1/"diagNE") — `cs:17-19`.
- `MatA`/`MatB`/`Shape` accessors mod-wrap the indices; `Shape` indexes `TileCompositor.Shapes` (`cs:21-23`).
- `CycleMatA/CycleMatB/CycleShape(int dir)` mutate the indices (`cs:28-30`).

**Grammar assembled in `CurrentGroundId`, `ShovelSelection.cs:26`:**
```
public static string CurrentGroundId => Shape == "full" ? MatA : $"{MatA}~{MatB}~{Shape}";
```
i.e. plain `matA` when shape is `"full"`, else `matA~matB~shape`. Read once at place-time in `ToolUseController.cs:71`. Shape vocabulary (13 tokens: full + 4 diag + 4 half + 4 quad) is `TileCompositor.Shapes`, `TileCompositor.cs:25-31`. `MaterialItem(material)` (`cs:34-48`) maps a material to the inventory block it costs/yields (for the HUD count).
