## Ranked findings

### 1. HIGH — Redundancy with the lighting docs is worse than the doc admits (it only confesses to bloom)
**Wrong/missing:** The doc self-flags only two overlaps (Bloom row: "*overlaps the lighting look doc*"; fireflies glow "OR overlay bloom (decide)"). But cross-reading the two docs, **at least five techniques appear in both** and are separately costed/prioritized in each:
- **Dust motes / pollen** — here it's the #2 "cheap high-impact win"; in `research_lighting_look.md` Tier 3 §8 ("light-catching particles: dust motes / pollen / fireflies as particles").
- **Fireflies** — here "High," Category 1; lighting doc Tier 3 §8.
- **Drifting cloud-shadow overlay** — here "High," Category 6; lighting doc Tier 3 §8 ("drifting cloud-shadow overlays").
- **LUT color grade + vignette** — here Category 5 ("High"/"Med"); lighting doc Tier 3 §7 and rubric §2.
- **Day/night sky gradient "→ global ambient/tint"** — this *is* the lighting doc's stated **#1 lever** ("dark, *colored* ambient multiplier… ← the #1 lever").

**Evidence:** `research_lighting_look.md:99-102` (Tier 3 §8), `:58` (LUT/vignette rubric), `:51` (ambient = #1 lever) vs this doc's backlog table (`:36`, `:39`, `:42`) and Categories 1/5/6.
**Fix:** Add a "who owns what" boundary line. The sky-gradient/ambient, LUT grade, vignette, and in-beam particles (dust/fireflies) should be **owned by the lighting docs and cross-referenced here (not re-costed)**; this doc keeps the *motion/particle-authoring* half. Otherwise a backlog built from both docs will schedule dust motes, fireflies, cloud-shadows, LUT, and ambient **twice**.

### 2. HIGH — Omits ambient wildlife / critters, which is the single most on-theme cozy-alive lever for a *bug* farm
**Missing:** Birds that land/peck/flush on approach, butterflies in spring, crows/seagulls, frogs, ground critters crossing — the Stardew "alive world" staple. The doc has fireflies-as-a-*light-particle* but no **fauna actors** (sprite actors with trivial waypoint/flee AI). For a game literally about bugs, ambient non-gameplay critters are both thematically perfect and cheap.
**Evidence:** Stardew and Animal Crossing lean on this heavily; the doc's own source table even name-drops "Stardew cloud-shadow **critters**" (`:142`) without turning it into a technique. Cost is low and it's pure client-local cosmetic (fits law #3).
**Fix:** Add a Category-1-or-new technique: "Ambient fauna actors — scripted sprite critters (bird land/peck/flush, butterfly drift, beach crabs), gated to biome/season/time, client-local, flee-on-proximity." Rank it a cheap-medium high-impact win.

### 3. HIGH — Under-serves the weather system it already has: no cheap rainy-day *wet-ground* look
**Missing:** The doc's only reflection/wet technique is **render-texture water reflections** flagged "Expensive / hero ponds only" (`:51`, `:87`). It completely omits the *cheap, weather-reactive* wet-ground pass: darken+desaturate ground tiles while raining, a specular sheen/"wet" overlay, and simple puddle-mask reflections that appear during/after rain. This is nearly free (a grade + overlay driven by the weather state, which already exists) and is one of the highest-impact rain tells in cozy games.
**Evidence:** Stardew's popular "Dynamic Reflections" mod exists precisely because reflective/splashy puddles on rainy days are a beloved, expected wet-day read (nexusmods.com/stardewvalley/mods/12831). The doc lists "weather-reactive grading" only under EXPENSIVE POLISH (`:52`) — but the *wet-ground darken* half of it is trivially cheap.
**Fix:** Add "wet-ground pass (rain): tile darken/desaturate + sheen overlay + optional puddle-mask reflection," costed **cheap** and tied to the existing weather state. Split "weather-reactive grading" so the cheap darken isn't buried with the expensive reflections.

### 4. MEDIUM-HIGH — Technically shaky idiom: VFX-Graph depth-buffer collision for rain splashes on the 2D Renderer
**Wrong/mis-scoped:** Category 1 rain row: "splashes = **VFX-Graph collide→trigger sub-emitter**" (`:73`). GPU-particle *Collide with Depth Buffer* is a 3D idiom and has a long history of **not working on the URP 2D Renderer** — the 2D Renderer doesn't populate a scene depth buffer the way the 3D renderer does, and depth-buffer VFX collision was unsupported/flaky until very recently (Unity 6 added "collision improvements," still 3D-oriented). In a 2D top-down game there's no geometry for drops to collide *against* — the "surface" is the ground/puddle mask, not depth.
**Evidence:** Unity Discussions threads "URP and Collide with Depth Buffer doesn't work?" and "VFX Collide With Depth Buffer in URP?"; VFX-Graph-on-2D-Renderer support is recent and its depth collision is the last-supported piece.
**Fix:** Drop the depth-buffer-collision approach. Spawn splashes from a **puddle/ground mask + spawn-on-emit at randomized ground positions** (or a flipbook splash keyed to the same puddle mask used for ripples). Re-cost: this is *cheaper* than the "1-2d VFX-Graph" line, not harder.

### 5. MEDIUM — Omits footprint / trail decals (snow & sand), a signature cozy detail the game's snow weather sets up for free
**Missing:** Player/creature tracks in snow and sand — Animal Crossing famously does species-specific prints on snow/beach. The doc's grounding category is all *shadows*, nothing about the player *leaving marks*. The game already has snow weather (the doc reskins leaves→snow at `:74`), so the setup cost is already paid.
**Evidence:** thegamer.com "Footprints Change Depending On The Species In Animal Crossing." Cheap as a fading decal/RenderTexture trail, client-local cosmetic.
**Fix:** Add "footprint/trail decals — fading tracks in snow/sand (and optional trampled-grass desire paths), client-local." Note the MP/pixel-perfect angle: snap to the pixel grid, purely cosmetic, no sim impact.

### 6. MEDIUM — Mis-prioritization: two "cheap hours-each wins" are really medium
- **"Pixelate scene transitions"** sits in **CHEAP HIGH-IMPACT WINS** ("hours each") but its own Category-5 row costs it "**med**" (`:44` vs `:129`). It needs a **Full Screen Pass Renderer Feature + custom shader + event wiring**. I verified it *is* feasible on the 2D Renderer (renderer features supported since URP 2022.1), so it's not wrong — but it's a day-ish job, not an "hours" quick win. Move it to Medium, or relabel the tier.
- **"Base-overlap + contact tufts"** is bundled into a top cheap win and called "**art-time only**" (`:100`). Across an entire *gpt-image-1-generated* library that's a **recurring per-asset hand-art cost on every new sprite**, not a one-time few-hours win. Flag it as an ongoing pipeline tax, not a quick win.

### 7. MEDIUM — Several load-bearing references are the *wrong perspective* (side-view), unflagged
**Wrong/missing:** Spiritfarer (water, reflections, dust), Ori (grass, leaves), Celeste (dust, squash), Kingdom Two Crowns (parallax) are **side-view / platformer**, not top-down. Most transfer, but **reflections especially do not**: Spiritfarer's water is viewed *side-on*, so a mirror reflection of sky/objects is the easy, high-payoff case. In top-down you look *down* at the water — reflections are a fundamentally different, lower-payoff problem, yet the doc cites "Spiritfarer (hand-crafted)" as the reflections reference (`:87`).
**Evidence:** Spiritfarer is confirmed side-view scrolling (pcgamingwiki, playdigious). The doc's own confidence flags (`:162-164`) catch the *Eastward/Celeste/Apico* caveats but not the **perspective** mismatch.
**Fix:** Add a one-line "perspective caveat" to the source table (side-view refs may not transfer 1:1), and specifically down-rate top-down water reflections' payoff — a wet-sheen (finding 3) buys more per hour than a top-down mirror.

### 8. MEDIUM-LOW — Interactive *water* omitted while interactive *grass* is covered
**Missing:** The doc has "player-parts-the-grass" displacement (`:84`) but no **player wading ripples / splash** when walking through shallow water — the natural water cousin, and a lovely pond/bug-farm touch. Same shader machinery (trigger → displacement/ripple sample).
**Fix:** Add "player wading ripple + splash (reuse the grass-displacer RenderTexture pattern for the water shader)."

### 9. LOW — Pixel-art gotcha inconsistency: bans rotating pixel sprites for particles, then recommends fractional rotation elsewhere
**Wrong:** The whole-Category-1 gotcha says *never live-rotate a shaped pixel sprite; use flipbooks* (`:76`). But later it recommends "lilypads = vertical Sine bob + **tiny rotation**" (`:86`), "arc toss" (`:111`), and "a **fraction of a degree** rotation" screenshake (`:115`) — all of which cause the exact nearest-neighbor edge-crawl the flipbook rule exists to prevent. Not fatal, but the rule should be stated **globally**, not scoped to particles.
**Fix:** Promote "no sub-pixel/fractional rotation of pixel sprites (flipbook or snap to discrete angles)" to the three-laws section, and reconcile the lilypad/screenshake/arc rows with it.

### 10. LOW — Other cozy-farm staples absent or under-promoted
- **Emote / speech bubbles** (Stardew's `!`/`…`/heart/sleep over NPCs & animals) — cheap, iconic cozy signal, totally absent.
- **Watered/tilled-soil darkening** — core farming *readability* look (see-at-a-glance what's watered); the grounding category is shadows-only.
- **Seasonal world recoloring** as a first-class lever (grass green→autumn→snow→spring) — only partially present as "season-swap sprite" + "snow ground tint" (`:70`, `:74`); for a season-driven farm this deserves its own row.
- **Tilemap auto-transition / terrain edge blending** (grass↔dirt↔water) — arguably authoring, not runtime FX, but it's a huge part of why cozy maps read as cohesive; at minimum flag it as an explicit scope boundary rather than silently omitting it.

### 11. LOW — The parallax "skip" is fair in substance but overstated in wording
**Nuance:** "Classic multi-layer parallax is a side-scroller trick that does NOT translate to top-down… **no horizon** in top-down" (`:55`) is too absolute — oblique cozy games and even top-down RPGs *do* use vertical/depth parallax (drifting cloud layers, slower-scrolling edge scenery; Celeste uses vertical parallax heavily). **But** the doc actually redeems itself: it includes the top-down-correct variants (edge scenery at 0.8-0.95×, cloud-shadows, atmospheric perspective) and correctly scopes the skip to "the play plane." So this is a wording overstatement, not a wrong recommendation. Soften "no horizon in top-down" to "no *play-plane* horizon to slide the world against."

### Minor MP gap
The pickup-magnet section correctly says "the authoritative pickup is a server event (don't let a tween decide ownership)" (`:121`), but doesn't address **visual reconciliation**: in MP an item can be flying toward *me* (local magnet) when the server awards it to another player. Add one line: "if the server awards elsewhere mid-flight, cancel/redirect the local magnet (pop-out), don't teleport."

## Ship-ready?
**Not quite — it has material gaps, but they're closeable in an editing pass, not a re-research.** The technical spine is sound (I verified the decal call is right, the parallax skip is defensible, and Full Screen Pass transitions are feasible on the 2D Renderer). The blockers to it *driving a backlog* are:
1. **De-dupe with the lighting docs** (finding 1) — otherwise you double-cost dust/fireflies/cloud-shadows/LUT/vignette/ambient.
2. **Add the three high-value, on-theme, cheap omissions that serve existing systems** — ambient wildlife (bug theme), weather-reactive wet-ground (weather system), footprint trails (snow weather) — findings 2, 3, 5.
3. **Fix the one shaky idiom** — VFX-Graph depth collision for 2D splashes (finding 4) — and re-tier the two mis-scoped "cheap wins" (finding 6).

Close those and it's a genuinely strong catalog. As-is, a team building straight from it would double-schedule lighting work and ship a farm that's missing the exact rain/season/critter touches a cozy player notices first.
