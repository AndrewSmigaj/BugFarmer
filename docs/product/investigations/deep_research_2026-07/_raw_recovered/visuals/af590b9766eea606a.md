# Verdict: URP with the 2D Renderer (definitively)

This project runs the **Universal Render Pipeline with the 2D Renderer (Renderer2D / light-based 2D pipeline)**, active project-wide. Every lighting decision hinges on this, and it is confirmed at every level:

- `BugFarmerClient/Packages/manifest.json` — `"com.unity.render-pipelines.universal": "17.2.0"` (URP 17 = Unity 6 era), plus the full 2D package set (`com.unity.2d.tilemap`, `2d.animation`, `2d.aseprite`, etc.).
- `BugFarmerClient/Assets/Settings/UniversalRP.asset` (guid `681886c5eb7344803b6206f758bf0b1c`) — the `UniversalRenderPipelineAsset`. `m_RendererType: 1` and its `m_RendererDataList` points at the Renderer2D data (guid `424799608f7334c24bf367e4bbfa7f9a`).
- `BugFarmerClient/Assets/Settings/Renderer2D.asset` — a **`Renderer2DData`** (2D Renderer). Confirmed by its `m_LightBlendStyles` block (Multiply / Additive / Multiply-with-Mask / Additive-with-Mask) and `m_DefaultLitMaterial` / `m_DefaultUnlitMaterial` — that structure only exists on the URP 2D renderer.
- `BugFarmerClient/ProjectSettings/QualitySettings.asset` — every quality tier sets `customRenderPipeline` to the UniversalRP asset guid `681886c5…`.
- `BugFarmerClient/ProjectSettings/GraphicsSettings.asset` — `m_RenderPipelineGlobalSettingsMap` maps `UniversalRenderPipeline` to the global settings asset (guid `93b439a3…`). (The legacy `m_CustomRenderPipeline: {fileID: 0}` slot being empty is normal for URP; the assignment lives in Quality + the global-settings map.)
- Supporting assets: `Assets/UniversalRenderPipelineGlobalSettings.asset`, `ProjectSettings/URPProjectSettings.asset`, and a URP 2D scene template at `Assets/Settings/Scenes/URP2DSceneTemplate.unity`.

Because it's the 2D Renderer, `Light2D` is the real lighting system and sprites must use a **Sprite-Lit** material to receive it — which is exactly what the code does (see below).

# 1. How the world renders

Main gameplay scene: **`BugFarmerClient/Assets/Scenes/SampleScene.unity`**. Core renderer: **`BugFarmerClient/Assets/Scripts/World/TilemapManager.cs`**.

**Ground tiles** — a real Unity **`Tilemap` + `TilemapRenderer`**. `TilemapManager` holds `[SerializeField] private Tilemap groundTilemap` and writes tiles via `groundTilemap.SetTile(...)` (around line 786). Tiles are built in `BugFarmerClient/Assets/Scripts/World/TileDatabase.cs`: a PNG from `Resources/Tiles/{id}` is turned into a `Sprite` with `PPU = texture width` so any tile fits exactly one cell, wrapped in a `ScriptableObject Tile`. In `SampleScene.unity` the `TilemapRenderer` is `m_SortingLayerID: 590243485`, `m_SortOrder: 0`, `m_Mode: 0` (Chunk mode).

**Occupants** (blocks like dirt_block/stone_block, plants, lamps, trees) — one **`SpriteRenderer` per occupant GameObject**, pooled. Created in `TilemapManager.cs` ~lines 843–908:
- `sr.sortingLayerName = "Occupants"` (a custom sorting layer that must exist in the project).
- Y-sort: `sr.sortingOrder = -cellPos.y` (lower Y draws in front).
- `worldPos.z = -0.1f` to sit just in front of the tilemap.
- Sprite scaled to the DB's target pixel size; `BoxCollider2D` fitted to sprite bounds.
- Tree fruit overlays are separate SpriteRenderers on `"Occupants"` at `sortingOrder = -cell.y + 1`.

**Bugs / swarms** — SpriteRenderers driven by `BugFarmerClient/Assets/Scripts/Bugs/BugVisual.cs` and `BugFarmerClient/Assets/Scripts/Entities/SwarmVisual.cs`. Y-sorted by position: `Renderer.sortingOrder = -Mathf.FloorToInt(pos.y) + 1`. Other sprite entities: `Entities/RemoteEntity.cs`, `Entities/StrikeVfx.cs`, `Bugs/CentipedeTrail.cs`, `World/GroundItemVisual.cs`.

**Material on all of these:** the shared 2D **lit** material from `BugFarmerClient/Assets/Scripts/World/LitMaterials.cs`. `LitMaterials.Lit` does `Shader.Find("Universal Render Pipeline/2D/Sprite-Lit-Default")` and caches **one** shared `Material` instance (to preserve batching). `LitMaterials.Apply(...)` is called on: the ground tilemap renderer (`TilemapManager.cs:88`), occupants (`:860`), tree fruit (`:370`), bugs/swarms (`SwarmVisual.cs:209`), remote entities (`RemoteEntity.cs:53`), strike VFX (`StrikeVfx.cs:76`), centipede trail (`CentipedeTrail.cs:79`), ground items (`GroundItemVisual.cs:43`), and the player + gear children (`DayNightController.cs:193`). So essentially the **entire world is rendered with `Sprite-Lit-Default`** and receives 2D lights. (If the shader isn't found, code logs a warning and sprites silently stay unlit — a fallback path worth knowing.)

# 2. The camera

- **Orthographic.** In `SampleScene.unity` the main Camera has `orthographic: 1`, `orthographic size: 7.7` (the recovery/backup scene uses 10; template scenes use 5).
- **No Pixel Perfect Camera.** The scene's camera data shows `m_PixelPerfect: 0` / `m_OverridePixelPerfect: 0` (these are `UniversalAdditionalCameraData` flags, not a `PixelPerfectCamera` component). No `PixelPerfectCamera` component is present in any scene.

The dominant art convention is **16 px = 1 cell = 1 world unit (PPU 16)**: `CharacterComposer.cs` (`W=16, H=32, PPU=16`), `GroundItemVisual.cs` ("icons & objects are PPU 16 = 1 cell"), `RemoteEntity.cs` ("16x32 @ PPU 16"), and `TileDatabase` sets PPU = texture width so a 16 px tile → 1 unit. # 3. Current lighting — "just point and spot lights" plus a global day/night light

All lighting is `UnityEngine.Rendering.Universal.Light2D`, created **programmatically at runtime** (very little is baked into the scene). No 3D `Light`, no `GlobalLight` class of their own. The pieces:

**A. Global day/night light — `BugFarmerClient/Assets/Scripts/World/DayNightController.cs`**
- Owns exactly one `Light2D` of `LightType.Global`. On `Start()` it adopts the first existing global light in the scene and **disables any extras**, creating one only if none exist (comments call out a long-standing bug where `SampleScene` shipped a static Global Light 2D pinned at intensity 1 defeating night).
- Time of day is derived from the authoritative sim tick: `timeOfDay = ((SimulationTick + DayOffsetTicks) % 8400) / 8400`, one day = 14 min (`DayTicks = 8400`). `WorldEnv` opcode 91 carries `day_offset_ticks` + weather.
- Drives the global light's **intensity** (`Mathf.Lerp(nightIntensity, 1f, Daylight)`, `nightIntensity = 0.20`) and **color** (white → warm amber `dawnDuskColor` at dawn/dusk → moonlit blue `nightColor` at night). `DaylightAt(t)` is a smoothstep day→dusk→night→dawn curve.
- Weather modifiers: rain `intensity *= 0.85` + cool desaturated tint; drought `intensity *= 1.08` + warm tint. Lightning strikes add an additive over-bright flash (`LightningFlash`) that decays each frame.
- Exposes static `Daylight` (0..1) that all point lights read to fade themselves.
- Note the **static scene light still exists**: `SampleScene.unity` contains a GameObject "Global Light 2D" with `m_LightType: 4` (Global), `m_Intensity: 1`, white — this is the one `DayNightController` adopts and then drives.

**B. Lamp / torch point lights — `BugFarmerClient/Assets/Scripts/World/LampLight.cs`**
- `LampLight` adds a `Light2D` of `LightType.Point`, configured with `pointLightOuterRadius = radius`, `pointLightInnerRadius = radius*0.25`, color, base intensity. Each frame it self-ramps: `intensity = baseIntensity * (1f - DayNightController.Daylight)` — off at noon, full at night.
- Data-driven: attached to placed occupants whose entity has a `world.light` block. `TilemapManager.cs:878–886` reads `def.World.LightRadius/LightColor/LightIntensity` (parsed in `Data/EntityDatabase.cs:475–479`, defaults radius 4, intensity 1, warm color `(1, 0.82, 0.55)`) and spawns a child `LampLight` (counter-scaled so radius stays in world units, and clearing stale pooled lights first).
- Fireflies carry their own tiny warm point light: `SwarmVisual.cs:261` `AddComponent<LampLight>().Configure(1.6f, (1, 0.82, 0.35), 0.9f)`.

**C. Player personal light + flashlight cone — `PlayerNightLight` (in `LampLight.cs`, lines 55–120)**
- Added to the local player by `DayNightController.EnsurePlayerLight()`. Client-visual only, driven by the equipped hotbar item:
  - Item with a `world.light` block (torch/lamp) → radial `LampLight` glow of that radius/color.
  - `tool_type == "flashlight"` → a child `Light2D` **cone**: a Point light with a narrow angle (`pointLightInnerAngle = 30`, `pointLightOuterAngle = 70`, outer radius 8), warm white, rotated toward the mouse each frame; intensity scales with night.
  - Otherwise → no glow (Terraria-style; you must hold/stand near a light at night).
- This is literally the "point and spot lights" the owner described — the flashlight cone is a URP-2D point light with inner/outer angles (URP has no separate 2D spot type; a narrow-angle point light is the cone).

**Materials lit vs unlit:** world sprites are **lit** (`Sprite-Lit-Default`, via `LitMaterials`). Any sprite that never gets `LitMaterials.Apply` falls back to Unity's default sprite material (unlit) — but in practice all gameplay sprites are wired lit. UI is uGUI (separate, unaffected).

**Debug/tuning hooks:** `Debug/DebugOverlay.cs:232–236` exposes a live "Night darkness" slider (`DayNightController.DebugNightIntensityOverride`, range 0.02–0.6); `F7` cycles day/night preview stops; `F8`-style night-floor override noted in code.

**Related atmosphere (not lights, but coupled):** `BugFarmerClient/Assets/Scripts/World/RainController.cs` — reads `orthographicSize` to build a rain overlay, sets `RainController.Raining` (which dims the global light) and triggers lightning flashes.

# 4. Post-processing — effectively none active

- **The scene camera has post-processing disabled:** `SampleScene.unity` camera data shows `m_RenderPostProcessing: 0` (plus `m_VolumeLayerMask` / `m_VolumeTrigger` at defaults). There is **no `Volume` GameObject** placed in any scene.
- A URP default volume profile exists at `BugFarmerClient/Assets/DefaultVolumeProfile.asset` (wired via `Assets/UniversalRenderPipelineGlobalSettings.asset` as the default-settings volume profile). It contains the stock Bloom / Tonemapping / ColorAdjustments / Vignette overrides, but **Bloom `intensity` is 0** (i.e. no visible bloom) and `UniversalRP.asset` has `m_VolumeProfile: {fileID: 0}`. With the camera not rendering post-processing, none of it takes effect in-game.
- Net: **no bloom, no global post FX currently doing anything.** The only screen-wide "grade" today is the day/night global `Light2D` tint/intensity in `DayNightController`.
