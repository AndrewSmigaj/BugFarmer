# Visual-FX / Atmosphere Inventory — Bug Farmer (2D Unity, URP 2D)

**Scope note:** All animation is **procedural C#** — there are **zero `.anim` clips and zero Animator `.controller` assets** in the project (`find … -name '*.anim' -o -name '*.controller'` → empty). There are **no custom shaders** (`*.shader`/`*.shadergraph` → none) and **no `.mat` material assets** — every material is created at runtime via `Shader.Find(...)`. No DOTween, no Cinemachine (packages are only the `com.unity.2d.*` family). The 2D renderer has **no render features** (`Assets/Settings/Renderer2D.asset` → `m_RendererFeatures: []`).

## 1. Weather / environment

- **Doc:** `docs/product/architecture/architecture_weather.md` — status line reads **"v1 IMPLEMENTED (rain-only)"**. v2 (per-cell deterministic rain) is designed but deferred.
- **Rain — implemented, and genuinely more than a flat sheet:** `BugFarmerClient/Assets/Scripts/World/RainController.cs`. Programmatically-built `ParticleSystem`s: parallax streak layers (data-driven `LayerSpec` presets — Light = 1 gentle layer; Heavy = intense base + darker-drops layer), a billboard **splash/ripple** layer, **gusting wind** (streak `velocity.x` breathed by `Sin` + `PerlinNoise` each frame), and lightning strikes (Heavy only) that drive an additive flash on the global light + delayed synth thunder. Layers are sized to the live camera view and rebuilt on zoom/intensity change. Materials are `Sprites/Default` (unlit).
- **Server side:** `nakama/…/handlers_env.go` (referenced in the doc) schedules showers (30%/day) and does one-shot watering. Wire = OpCode 90 (DebugWorld, F8) / OpCode 91 (WorldEnv broadcast). Weather states on the wire are only `""` / `"rain"` / `"stop"`.
- **Fog — NOT implemented.** The CLAUDE.md description ("layered scrolling noise + parallax + light interaction") is **aspirational only**. The single mention in code is a comment in `RainController.cs:20` ("Fog/dust (BACKLOG) will be SEPARATE self-activating components"), and it lives in `docs/product/BACKLOG.md:1272` as a future research pass. No fog code, no noise texture, no fog component exists.
- **`"drought"` weather — dead/aspirational path.** `DayNightController.cs:138-149` tints the global light for `Weather == "drought"`, but the server never sends that value (wire doc lists only rain/stop), so it never fires today.
- **Dust storms** — BACKLOG only (`BACKLOG.md:1275`).
- **`ParticleSystem` appears in exactly ONE file** in the entire codebase: `RainController.cs`. Rain is the only particle effect in the game.

## 2. Day/night, ambient color, global tint

- **`BugFarmerClient/Assets/Scripts/World/DayNightController.cs`** — a real time-of-day system driven by the authoritative sim tick (one day = 8400 ticks = 14 min). Drives **exactly one URP `Light2D` global light** through a dawn/day/dusk/night curve (`DaylightAt`): smoothstep golden dusk → deep-blue night floor (`nightIntensity` 0.20, `nightColor` moonlit blue) → smoothstep dawn. Warm amber tint at transitions (`dawnDuskColor`), cooler/desaturated overcast tint while raining, blue-white additive on lightning. Clock UI + F7 preview + F8 night-darkness slider.
- **Global tint is done via the 2D global light color/intensity, not post-processing.** There is **no sky, no background gradient, no parallax sky.** Camera clear flags = SolidColor with a flat dark blue-gray (`SampleScene.unity:928-929`); no skybox or background-layer script anywhere (`grep skybox|background gradient` → none).
- **Lighting model:** one ramped global (multiply → darkens) + additive point-lights. Local night visibility comes only from point lights (`LampLight`, `PlayerNightLight`).

## 3. Post-processing & camera FX

- **URP Volume profile exists but is effectively OFF.** `BugFarmerClient/Assets/DefaultVolumeProfile.asset` contains every URP override (Bloom, Vignette, ChromaticAberration, DepthOfField, FilmGrain, MotionBlur, ColorAdjustments, Tonemapping, LensFlare, etc.) — **all at zero / neutral defaults** (Bloom intensity 0, Vignette intensity 0, etc.). This is Unity's stock default profile, untouched.
- **The camera does not even render post-processing:** `SampleScene.unity:898` → `m_RenderPostProcessing: 0`. There is no scene Volume with a custom profile. So **no bloom, no vignette, no color grading is active** — including on the glow-mushroom/fireflies/lamps that would most benefit.
- **No screen shake** anywhere (`grep -i shake|trauma` → none). **No pixel-perfect camera** (`m_PixelPerfect: 0` in scene; no `com.unity.2d.pixel-perfect` package) — pixel art can sub-pixel shimmer.
- **Camera = plain smooth-follow only:** `BugFarmerClient/Assets/Scripts/Player/CameraFollow.cs` (`Vector3.SmoothDamp`). No shake, no zoom punch, no look-ahead, no bounds.
- **Screen fade (the one full-screen effect):** `BugFarmerClient/Assets/Scripts/UI/ScreenFade.cs` — an `OnGUI` black-quad fade for cross-zone transitions. Intro juice in `UI/IntroOverlay.cs` and `UI/OpeningSequence.cs`.

## 4. Sprite styling / shaders

- **No custom shaders, no outlines, no normal maps, no dissolve.** World sprites use one of two built-in materials:
  - **Lit:** `BugFarmerClient/Assets/Scripts/World/LitMaterials.cs` — a single shared `Universal Render Pipeline/2D/Sprite-Lit-Default` material, applied to tiles, occupants, ground items, bugs, remote players, corpses so they **receive** Light2D. This is the only "styling" — plain lit sprites, **no normal maps** (so lighting is flat/uniform per sprite, no surface relief).
  - **Unlit:** `Sprites/Default` for rain, tool trails, the bug-release indicator.
- **Hit-flash: yes, but color-tint only (no shader).** `BugFarmerClient/Assets/Scripts/Bugs/BugVisual.cs:71-72,156-161` — `SpriteRenderer.color` flips to red `FlashTint` on hit and a persistent light-red `DamagedTint` while damaged. It's a vertex-color tint, not a white-flash/emission shader.
- **Glow rendering — split, and inconsistent:**
  - **Fireflies:** real `Light2D`. `BugFarmerClient/Assets/Scripts/Entities/SwarmVisual.cs:250-267` attaches a child `LampLight` (amber `Light2D`, radius 1.6) that ramps on at night. This is the one "biolumin" glow that actually casts light.
  - **Lamps / torches / campfire / lantern / candelabra / lamp_post:** real `Light2D` via `BugFarmerClient/Assets/Scripts/World/LampLight.cs`, data-driven from the entity `world.light` block (`TilemapManager.cs:871-886`, parsed in `Data/EntityDatabase.cs:471-479`). Only **placeables** carry `light` blocks.
  - **Glow-mushroom — does NOT glow (no light).** `nakama/data/entities/occupants.json:401` (`mushroom_glow`) has **no `light` block**; in fact `occupants.json` contains **zero** light blocks (`grep -c '"light"'` → 0). It renders as an ordinary lit sprite — no Light2D, no emission, no additive halo. A "Glowing Mushroom" that emits no light is a concrete gap.
- **Drop-shadow fake for flyers:** `SwarmVisual.cs` gives fence-ignoring bugs a semi-transparent black sprite copy offset below them as an "airborne" tell — the only shadow system in the game (no real blob shadows on grounded sprites/player).

## 5. Particles / juice

Present (all hand-rolled coroutines / `Mathf.Lerp` / `SmoothDamp` — no tween lib):

- **Tool animation:** `BugFarmerClient/Assets/Scripts/Player/PlayerToolAnimator.cs` — procedural swing/sweep/stab/pour with ease-out, plus a **`TrailRenderer`** white fade on sweeps (net/scythe). Good, real juice.
- **Ground-item juice:** `BugFarmerClient/Assets/Scripts/World/GroundItemVisual.cs` — sinusoidal bob, hover **highlight** tint, pickup **magnet** tween (ease-in fly-to-player + shrink), shrink-fade despawn.
- **Bug animation:** `BugVisual.cs` — cosmetic wing-flap frame cycling (flap-then-glide for butterflies, continuous buzz for flies), vertical bob, and a strike **lunge** (out-and-back jab, sin envelope).
- **Predation corpse pop:** `BugFarmerClient/Assets/Scripts/Entities/StrikeVfx.cs` — a dead-prey sprite pops in with ease-out-back overshoot, holds, then alpha-fades.
- **Centipede/millipede body:** `BugFarmerClient/Assets/Scripts/Bugs/CentipedeTrail.cs` — procedural segmented body reconstructed from the head's rendered path (per-segment rotation along tangent).
- **Water-can droplet indicator:** `BugFarmerClient/Assets/Scripts/World/WaterDroplet.cs` — runtime-generated teardrop sprite that bobs.
- **Mining feedback:** `BugFarmerClient/Assets/Scripts/World/BreakingVisual.cs` + 4 crack-overlay sprites `Assets/Resources/Effects/break_stage_1..4.png` — sprite-swap only.

- **No foliage/tree sway, no grass wind** (`grep sway|foliage|treewind` → none). Trees/plants are static sprites.

## 6. Conspicuously ABSENT vs a polished 2D indie game

- **No active post-processing at all** — bloom/vignette/color-grade are configured-to-zero and the camera has post-processing disabled (§3). The most common "instant polish" layer for a lit 2D game (bloom on lights/glow, a graded LUT, subtle vignette) is entirely dormant. BACKLOG itself flags "URP post-process color-grade while raining" as not-yet-done (`BACKLOG.md:1279`).
- **No normal-mapped lighting** — sprites are `Sprite-Lit-Default` with no normal/mask maps, so the single global + point lights wash sprites flatly; no surface relief, no rim/shape from light. No secondary textures anywhere.
- **No ambient occlusion / contact shadows / blob shadows** — grounded objects and the player cast nothing; the only "shadow" is the flyer drop-shadow fake.
- **No screen shake / hit-stop / impact feedback on the camera** (§3) — combat has a bug color-flash but no camera juice.
- **No pixel-perfect camera** — pixel art isn't snapped/upscaled cleanly (sub-pixel shimmer risk).
- **No fog / dust / atmospheric depth layers** — the CLAUDE.md fog description is unbuilt (§1); no depth haze, no vignetting of distance, no god-rays.
- **Flat sprites, no material variety** — one shared lit material for the whole world; no per-object emission, no glow/additive materials (glow-mushroom is the clearest casualty).
- **No sky / horizon / background gradient / weather-reactive sky** — flat solid-color clear.
- **No animation clips / state machines** — all motion is code; fine, but there's no eased UI motion system, no particle authoring, and juice is unevenly applied (tools & pickups have it; world flora, water, and the environment do not).

**Net:** the *systems skeleton* for atmosphere is real and well-factored — a tick-driven day/night with one correct global light, a genuinely layered rain system, data-driven point lights, and per-entity procedural animation. What's missing is the **screen-space / material polish layer**: post-processing (bloom/grade/vignette), normal-mapped or emissive sprite lighting, real shadows/AO, pixel-perfect rendering, environmental particles (dust/pollen/leaves), foliage/water motion, background parallax, and camera juice.
