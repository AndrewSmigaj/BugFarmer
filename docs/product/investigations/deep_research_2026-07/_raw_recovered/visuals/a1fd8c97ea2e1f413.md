  Ground    [][]string          // 32x32, [y][x], a floor-tile id ("grass","cave_floor",…)

## 2. The zonegen builder side

**File: `/mnt/c/Users/emily/BugFarmer/tools/zonegen/zonebuilder.py`**

- `ZoneBuilder` holds four per-cell grids (lines 71–74):
  ```
  ground[y][x]   base_tile string
  occ[(x,y)]     {"id","dir","anchor"?}
  surface[y][x]  semantic mask, one of SURFACES
  reserved[y][x] bool (claimed by a hard feature)
  ```
- `SURFACES = {"water","path","building","farm","forest","grass"}` (line 27). **There is NO `underground`/`cave` surface value.** The `surface` mask is authoring-only coordination between feature primitives — `save()` (lines 387–414) persists **only** `ground` + `occupants` + zone.json; `surface`/`reserved` are never written. On `load()` the surface mask is re-derived heuristically from tile id (`_tile_surface`, lines 43–49: only water/path/grass).
- Underground is NOT a mask value; it is expressed **structurally** in `/mnt/c/Users/emily/BugFarmer/tools/zonegen/features/cave.py`. Module docstring (lines 2–6) states the convention: builder ground = `cave_floor`, "carving" = recording cells to **leave open**, and **every non-carved cell gets a block occupant via `fill_solid`** (lines 282–320: `stone_block` base, plus ore-vein blocks). So a cell is "underground/buried rock" iff it carries a block-category occupant; "open tunnel/cavern" iff it was carved (no solid occupant). Base tile can be `cave_floor` (underground_passages) or `dirt` (ant_tunnels).
- `biome` is a ctor arg (default `"meadow"`, line 53) written straight to `zone.json` `biome_type` (line 397). A builder "knows" a cell is underground only by construction (it filled it solid, or it built a cave-floored zone) — there is no per-cell boolean it sets.

## Summary of where a signal could live/flow (data shapes only, no solution prescribed)

- **Per-cell "underground"**: derivable server-side at authoring/load from the two on-disk layers — ground tile (`cave_floor`/`dirt` under a cave build) and/or presence of a `category:"block"` solid occupant. It is currently *not* stored as its own field in `ChunkData`, `PlacedOccupant`, `TileDefinition`, or `zone.json`.
- **Per-cell "exposed to sky"**: would require a connectivity/flood-fill that does not exist yet; the raw input it needs (per-cell solid = `World.BlocksBugs`/`BlocksPlayers`, or the carved-vs-filled occupant layer) is already present both server-side and, zone-wide, client-side (`_blocksBugsZoneWide`).
- **Existing carriers** that already move per-cell/zone data server→client→renderer: the per-chunk `ChunkDataMessage` (ground + occupants, OpCode 44) and the zone-wide `ZoneCollisionMapMessage` cell-list (OpCode 106) → `_blocksBugsZoneWide` HashSet. The renderer already lights every sprite through a single Global `Light2D` (DayNightController) with per-lamp `LampLight` overrides — but reads no per-cell darkness input today.
