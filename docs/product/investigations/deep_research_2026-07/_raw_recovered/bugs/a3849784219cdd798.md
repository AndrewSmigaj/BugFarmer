# BEE species — reuse map for BugFarmer bug-sim mechanics

Bees map almost 1:1 onto the **wasp nest-predator chassis**, swapping "hunt prey → provision brood" for "forage nectar → provision honey+brood." Below, each bee mechanic is tagged **REUSE** (existing system, file:line) or **NEW** (nearest pattern to copy), with the determinism surface flagged.

Determinism legend (from `architecture_swarm_sync.md §0`, `docs/product/architecture/architecture_swarm_sync.md:26-37`): **LEDGERED** = zone-wide frontier-gated influence event the sim reads (must follow the frontier-sync recipe); **SERVER-ONLY soft state** = never hashed, never in snapshot, resets on restart (nests/broods/forage pools/host plants/stations all live here); **DISPLAY-ONLY** = cosmetic broadcast, never in the hash.

## 1. The wasp colony model (the bee template)

### NestState struct — REUSE, `nakama/modules/entities/nest.go:12-34`
All fields:
```go
type NestState struct {
	GridX, GridY    int
	EntityID        string // occupant type ("wasp_nest") — generic for future hives
	SpeciesID       string // the species this nest spawns ("wasp_common")
	Brood           int    // banked deposits, clamped at BroodCap
	ResidentSwarmID string // the patrol this nest owns ("" = none)
	RehatchAtTick   int64  // armed when the resident dies with brood banked (0 = unarmed)
}
```
The doc comment already anticipates bees: *"NestState is deliberately species-generic (bees later: a `Deposit` field + a yield item on the nest def)."* (`nests.go:27-28`). Tuning consts at `nest.go:22-34` (`NestBroodCap=9`, `NestHatchCost=3`, `NestHatchCount=3`, `NestRehatchDelay=1200`, `NestRecoveryDelay=3000`, `NestFoundingSize=4`, `NestDefendRadius=5.0`, `NestDefendRelease=10.0`, `NestDefendTicks=300`, `NestDepositRange=2.0`, `NestHomingTimeout=600`).

### Brood economy (hatch / +N / clamp / dormancy / recovery) — REUSE, `nakama/modules/world/nests.go`
- **Deposit + hatch** `depositBrood` `nests.go:196-221`: `if nest.Brood < NestBroodCap { nest.Brood++ }`, then `if nest.Brood >= NestHatchCost { … nest.Brood -= NestHatchCost; m.growSwarm(state, swarm, n) }` — cap-aware (holds brood at population cap).
- **Re-hatch / dormancy** `processNests` `nests.go:124-191` (runs every 30 ticks): a dead resident with banked brood re-staffs after `NestRehatchDelay` at a size equal to brood consumed; a brood-exhausted colony re-founds a fresh patrol only if prey is nearby (`nestHasPreyNearby` `nests.go:328-350`) after `NestRecoveryDelay`.
- **Daughter-hive spread** `processNestFounding` `nests.go:259-323`: a saturated patrol (`Count >= MaxSwarmSize`) with full brood founds a new nest near a prey cluster (`findNestSiteWithPrey` `nests.go:357-386`), gated by `SpeciesCaps[id].MaxNests`. Placement is server-authoritative via `broadcastWorldUpdate` (LEDGERED-class world-cell mutation; comment at `nests.go:256-258`).

### Hive trip state machine (hunt → home → deposit → rest) — REUSE, `nakama/modules/world/predation.go:121-199`
This is the core loop bees reuse (swap "hunt prey" for "forage nectar"). The nest lifecycle tree lives in `predationThink`, ownership order **defending > homing > feed-pause > hunt > rest**:
- **PROVISION/homing** `predation.go:169-198`: `if swarm.Phase != "homing" && swarm.Satiation >= predatorFullSatiation && swarm.NestKey != "" { swarm.Phase = "homing"; swarm.CarryingBrood = true; … }`; on arrival within `NestDepositRange` → `m.depositBrood(...)`, `swarm.Satiation = p.DepositSatiation` (rest). `predatorFullSatiation = 90.0` (`predation.go:42`) is BOTH the forage ceiling and the go-home trigger — the "no dead zone" 2-state forager loop. Homing timeout drops the brood (`predation.go:176`).
- Trip phase strings + carry fields on the swarm: `entities/swarm.go:82-89` (`NestKey`, `CarryingBrood`, `HomingStartTick`, `DefendUntilTick`, `DefendTargetID`).

### Orphan patrols — REUSE, `nakama/modules/world/nests.go:236-244`
`orphanNestResident`: a destroyed nest sets `resident.NestKey = ""`, `CarryingBrood = false`, and flips homing/defending back to feeding. An orphan *"never breeds, tethers to its last HomePos, still hunts/stings"* (`swarm.go:84`).

### Nest-only spawning (the `spawnSwarmForSpecies` skip) — REUSE, `nakama/modules/world/ecology_director.go:52`
Nest species are never free-reseeded by the Director: `if cap.MinPopulation > 0 && pop < cap.MinPopulation && cap.MaxNests == 0` — the `&& cap.MaxNests == 0` clause skips wasps/bees. Recovery is only through the prey-gated nest path. Zone config sets `wasp_common.initial: 0` (see §7) so wild swarms never spawn; the resident is minted by `nestSpawnResident` `nests.go:87-117`.

### How a nest is PLACED in a zone — REUSE, `nakama/data/entities/occupants.json` (wasp_nest)
Important: **the nest occupant has NO `world.nest` block.** It is a plain breakable occupant; the server links it to a species via that species' `predation.nest_occupant` field (`speciesForNestOccupant` `nests.go:31-38`, scanned at chunk load by `initNestsInChunk` `nests.go:44-68`). The `wasp_nest` def:
```json

 "name": "Wasp Nest", "category": "natural", "sprite_w": 24, "sprite_h": 28,
 "world": {
  "footprint": [1,1], "pivot": "bc", "blocks_players": false, "blocks_bugs": false,
  "breakable": {
   "hp": 4, "required_tool_type": "axe", "required_tool_tier": 1,
   "drops": [ {"item_id":"paper_nest","count":2,"chance":1.0},
              {"item_id":"wasp_larvae","count":2,"chance":0.8} ]

```
For a **bee hive**: add a `bee_hive` occupant here (same shape) + a `bees_common` species with `predation.nest_occupant: "bee_hive"`. That alone wires the whole colony/trip/brood machinery. The honey-yield field would be NEW on either the occupant `world` block or `NestState` (see §5).

### HostPlantState (milkweed breeding — the deplete+regrow shape) — REUSE, `nakama/modules/entities/host_plant.go:7-11`

### How a swarm targets food and 'feeds' (satiation) — REUSE, `nakama/modules/world/match.go:1309-1345`
Per-tick feeding: when `atFood`, `case "feeding": swarm.Satiation += species.FeedAmount * deltaTime` (clamped 100); if the source is depletable, `drain := consumeRate * float32(swarm.Count) * deltaTime` drains ground-items/stations via `consumeFood` AND directly decrements `ForagePools[...]. Nectar` (`match.go:1339-1344` — *"a big swarm exhausts it → the flower is skipped → starve"*). Cached target fields on the swarm: `TargetFoodID/X/Y/Depletable` (`swarm.go:49-52`), set at Think, O(1) at-food check.

**Bee note:** wasps have `feed_amount:0` and get satiation from KILLS (`FeedPerKill`, `applyPredationStrike` `predation.go:362`). A bee would instead use the standard `feed_amount` nectar path above (like flies/butterflies) but keep the NEST provisioning loop — i.e. a bee's `predation` block would have `nest_occupant` set but `prey:[]`; the trip trigger `swarm.Satiation >= predatorFullSatiation` already works off nectar-satiation, so the homing loop needs **no change**. (The one wrinkle: nest predators currently derive `huntCeiling` and re-acquire prey — a nectar-forager bee needs the forage/feed path to run instead of the hunt path. This is the main NEW branch: teach the nest lifecycle in `predation.go:236-253` to fall through to the shared forage block when `p.Prey` is empty.)

## 3. Aggro + combat

### Aggro-on-damage recall — REUSE, `nakama/modules/world/nests.go:417-431` + call site `handlers_world.go:465`
`recallNestDefenders` sets the resident to `Phase="defending"`, `DefendTargetID=attackerID`, `DefendUntilTick=now+NestDefendTicks`, and `NextThinkTick=now` (respond this tick). Called from the tile-break DAMAGE path: `handlers_world.go:465  m.recallNestDefenders(state, msg.GridX, msg.GridY, userID)`. Also passive aggro: a player within `NestDefendRadius` of the nest triggers defending in `predationThink` `predation.go:127-134`. This is exactly the *"defensive aggression when a player harvests"* mechanic — a honey-extract action would call `recallNestDefenders` the same way.

### Sting mechanics (player HP, OpCode 94, invuln/knockback) — REUSE, `nakama/modules/world/handlers_player.go`
- `applyBugAttackToPlayer` `handlers_player.go:26-96`: `player.HP -= damage`; builds `PlayerDamageMessage{HP, MaxHP, Damage, SourceSpecies, KnockDX, KnockDY}`; on `HP<=0` faints (refill + respawn). Sent presence-TARGETED via `sendPlayerDamage` `handlers_player.go:151-166` on **OpCode 94** (`OpCodePlayerDamage`; header `handlers_player.go:12-14`).
- `checkBugAttacks` `handlers_player.go:101-123`: any player within `stingRange=1.5` of the swarm centre takes `species.AttackDamage`; called per-tick in the match loop when `species.AttackDamage > 0` (`match.go:1301-1303`).
- Invuln/knockback: shared `playerInvulnTicks=10` (1s) gate `handlers_player.go:45`; knockback vector = normalized player-minus-swarm direction `handlers_player.go:57-65`. Regen `processPlayerRegen` `handlers_player.go:127-147`.
- Wasp combat stats (bee reuses shape): `attack_damage:1`, `attack_cooldown:2.0`, `max_hp:3` in `species.json`.

Determinism: HP is **DISPLAY-ONLY / sim-inert** (`handlers_player.go:12-13`: *"Bug AI reads player CELLS (already on the ledger); HP rides the presence-TARGETED message"*).

### Per-swarm sting cooldown (the v1 mass-sting cap) — REUSE, `nakama/modules/world/handlers_player.go:37-49`
```go
cooldownTicks := int64(species.AttackCooldown * 10)   // attack_cooldown in seconds
if state.TickCount-swarm.LastAttackTick < cooldownTicks { return false }
```
`swarm.LastAttackTick` (`swarm.go:80`) is the per-swarm anchor — one sting per swarm per cooldown, "one victim per swarm per tick" (`handlers_player.go:120-121`). This is exactly the cap referenced in `docs/product/BACKLOG.md:598-599`: *"bee mass-sting damage scaling (per-swarm cooldown is the v1 cap)."* So a swarm of 20 bees still stings at the single-swarm rate in v1 — future per-bee scaling is backlogged.

### feed_pause_ticks — REUSE, `nakama/modules/world/predation.go:207-212` + `predation.go:371-374`
`FeedUntilTick` parks a predator on its kill for the dwell; set in `applyPredationStrike` when `p.FeedPauseTicks > 0`. Field `swarm.go:79`; species knob `species.go:137`. Bees (no prey) won't set it, but the mechanism is there if a bee "settles on a flower" beat is wanted.

### Predator LOS (BugCollision.LineBlocked) — REUSE, `BugFarmerClient/Assets/Scripts/Bugs/BugCollision.cs:75-86`, used at `Entities/SwarmManager.cs:667`
Client-side per-bug LOS gate: `if (BugCollision.LineBlocked(pbPos, qbPos)) continue;` — the authority client uses it during per-bug strike selection. Server-side leg clamping uses `RaycastClampWithBlock` (`entities/swarm.go:310-338`) and `IsBlockedForSpecies`. `flies_over_fences:false` on the wasp means it respects pens; a bee would likely also be `false`. This is hash-bearing (per-bug positions are hash state — `species.go:104-109`).

## 5. Station harvest analog — "hive stores honey over time, player extracts N (and gets attacked)"

Three existing accumulation/extraction patterns; the honey hive is a **NEW blend** of them:

### (a) Compost StationState — accumulate-then-drain (bugs consume) — REUSE for the accrual shape, `nakama/modules/entities/station.go:10-24`

### (c) Fruit tree — accumulate-then-hand-pick / auto-drop — REUSE for a no-panel harvest, `nakama/modules/world/handlers_farming.go`

FruitTreeStates are SERVER-ONLY soft state.

**Recommended honey design:** put a `HiveState.Honey float32` (accrues on each brood deposit, or on a slow clock) as SERVER-ONLY soft state on/beside `NestState` (which the code already flags for a bee `Deposit` field, `nests.go:27-28`). Extraction = a **tree-harvest-style OpCode** (hand-pick N honey → `AddItem`) OR a **craft-station-style collect panel**; either way, fire `recallNestDefenders` on extract for the aggression. Honey itself is **DISPLAY-ONLY / inventory state** (like fruit count / craft output) — it is NOT a bug-sim input, so no new ledger event is needed for honey. Only if bees *feed on stored honey* (a sim read) would it need `FOOD_CONSUMED`-style ledgering.

### Ledger-event glossary (verbatim, `docs/product/architecture/architecture_swarm_sync.md:29-37`)
`PLAYER_CELL_ENTER/_LEAVE` (player pos → flee/seek) · `SWARM_SET_TARGET` (movement leg + hunt strike params) · `BUG_REMOVED` (catch/melee/predation/gnaw) · `SWARM_SPAWNED` · `SWARM_REPRODUCED` · `SWARM_SPLIT`/`_MERGE` · `ITEM_ROTTED`/`FOOD_CONSUMED` (food registry, level 0 = gone) · `OCCUPANT_BLOCKS_BUGS` (collision set) · `TREE_FRUIT_GROW`/`_DROP` (farming, not bug-sim). The load-bearing invariant (`:18-23`): *everything the deterministic bug sim READS must arrive via a frontier-gated zone-wide influence event or a snapshot — never a chunk-scoped on-receipt message.*

## 6. New-species checklist (what adding a species takes)

The **dragonfly is the "chassis proof"** — `docs/product/BACKLOG.md:595`: *"Dragonfly: prey:[wasp_common] — pure data + sprite (the chassis proof)."* A predator species is data + sprite only. A bee is a bit more (the nectar-forage-nest hybrid branch noted in §2), but the data footprint is:

1. **`nakama/data/species.json`** — one `BugSpecies` block (full field list at `entities/species.go:11-142`). Key fields: `category` (`"swarm"` vs `"individual"` — bees = `"swarm"`, `species.go:15`), `base_speed/vision_range/…`, `attractions_by_phase` (nectar flower ids for feeding), `feed_amount` (>0 for a nectar forager), `attack_damage/attack_cooldown` (sting), `max_hp`, `net_size/catch_condition`, `lifespan_secs`, `carcass_item`, `sprite_id`, and a **`predation` block with `nest_occupant:"bee_hive"`** (+ empty `prey`) to opt into the nest/trip/brood chassis. Client mirror: `BugFarmerClient/Assets/Resources/Data/species.json` (dual copy).
2. **Sprite** — `BugFarmerClient/Assets/Resources/Bugs/<sprite_id>.png` (e.g. `Bugs/bees_common.png`; the dir already holds `beetle_carrion.png` etc.). Use the `add-object`/`regenerate-sprite` skills.
3. **Hive occupant** — a `bee_hive` entry in `nakama/data/entities/occupants.json` (copy `wasp_nest` shape: breakable, drops honeycomb/larvae; add any honey-yield field). Its sprite via `add-object`.
4. **Per-zone spawn config** — a `species_caps` block + optional `spawn_areas` + Director bands in each zone's `zone.json` (see §7).

### Brood system: nest vs compost/milkweed — which bees use
Two reproduction chassis exist:
- **Nest brood** (`NestState`, predators): brood banked at the hive, hatches into the resident, prey/full-load-gated. `nests.go` + `predation.go`.
- **Visible brood** (`BroodState`, non-predators): flies/butterflies LAY eggs at compost/milkweed/ground-pile; eggs→maggots→hatch on a slow clock. `entities/brood.go`, `world/brood.go`. The redirect is `reproduceSwarm`→`layIntoBrood` `brood.go:71-96`.

**Bees should use the NEST brood chassis** (hive-based colony, resident patrol, provisioning trip) — it's the entire template in §1. The compost/milkweed `BroodState` is for source-laying non-nest breeders and doesn't fit a hive.
