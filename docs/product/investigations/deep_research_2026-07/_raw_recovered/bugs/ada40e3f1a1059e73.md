# Implementation Plan — ANTS as a simulated colony species

## Headline determinism story (the whole plan hangs on this)

The sim is hybrid: a single authoritative Nakama Go match goroutine runs the swarm-**center** AI (Think, `FindNearbyFood`, legs, nests, broods) and emits the influence ledger; clients replay `SWARM_SET_TARGET` legs and compute per-bug positions; the authority *client* only selects individual predation-strike victims. I verified the late-join snapshot (`OpCodeLateJoinSnapshot` 72, `messages.go:1013`) carries **`Swarms` + `Food` only** — never `NestStates`/`BroodStates`/`ForagePools`. That confirms the design-doc lever: **all center-AI soft state (satiation, nest brood, and now colony memory) lives only on the server; its sole observable output is the `SWARM_SET_TARGET` leg every client already replays.**

Consequence: the entire ant feature adds **zero new ledger events, zero `ComputeStateHash` fields, zero client snapshot fields, zero client sim code.** Everything rides existing events:
- movement → existing `SWARM_SET_TARGET` (via `emitLeg`, `predation.go:581`)
- hatches → existing `SWARM_REPRODUCED` (via `depositBrood`→`growSwarm`)
- carrion eaten → existing `FOOD_CONSUMED` (via `consumeFood`, `handlers_farming.go:1323`)
- ant_mound placement on daughter-founding → existing `broadcastWorldUpdate` (crop/nest-placement class)

Colony memory is classified exactly like `NestState.Brood`: **server-only soft state**, iterated with `sortedStringKeys`, drawing only `state.Rng`, **excluded from `buildWorldSave`** (the lens rule), never hashed, never snapshotted. It resets on server restart and rebuilds as scouts re-register — which is the desired "ages out / doesn't persist" behavior.

## Design-question resolutions (recommendation + rationale)

**1. Species decomposition → 2 sim species + 1 non-sim fixture.**
- `ant_worker` — the forager. `category: "swarm"`, deliberately **small** (`min_swarm_size` 2, `max_swarm_size` 5) so a stream of workers to one site reads as a *line* (the Fun/Legibility lens, `lenses.md:91`). Nest resident, empty prey list, carrion attractions, `nest_occupant: "ant_mound"`.
- `ant_scout` — separate species, tiny (`min` 1 / `max` 2), wide wander, registers carrion. Separate species (not a mode) because its wander radius, home-range tether, and "don't provision" behavior differ, and a separate species keeps the branch in `predationThink` a clean species-flag check rather than intra-swarm role state (simpler determinism, no per-bug role bookkeeping).
- `ant_queen` — **NOT a forager sim species.** It is the colony fixture. The `ant_queen` entry already in `bugs.json` (value 500, catch_difficulty 5) is the catalog/mini-boss entry. Recommend the Queen be a **nest fixture / mini-boss combat encounter** layered on the `ant_mound` NestState in (4,0), implemented via the existing combat/breakable-occupant path — flag as separate combat/zone work, out of species-sim scope.

Rationale: reusing `category:"swarm"` (values are `swarm`/`individual`) keeps ants on the merge/split/leg machinery; two species is the minimum that gives the scout-explores / worker-streams split that makes the trail legible.

**2. Colony memory → per-nest, in a new `WorldState` side-map, server-only.**
```go
// entities/colony.go
type CarrionSite struct { GridX, GridY int; Strength float32 }
type ColonyMemory struct { Sites []CarrionSite } // bounded slice, weakest evicted
```
```go
// WorldState (state.go): NOT added to buildWorldSave, NOT hashed, NOT snapshotted
ColonyMemory map[string]*entities.ColonyMemory // key "gx,gy" of the ant_mound nest
```
Per-**nest** (not per-zone-per-species) so it bounds naturally with nest count (≤ `MaxNests`) and a daughter colony keeps its own trails. A slice (not a map) with a hard `maxColonySites` cap (e.g. 8) → **bounded standing count** = `MaxNests × 8` (Unbounded-Growth lens). Frontier-sync classification: **server-only soft state**, the `NestState`/`BroodState` contract — the sim reads it only to choose which leg to emit, and there is one server, so no cross-client read divergence is possible. Determinism obligations: `sortedStringKeys(state.ColonyMemory)`, sorted site iteration, `state.Rng` only. Must **not** be embedded in `SwarmState` (that struct is snapshotted+hashed) and must **not** enter `buildWorldSave` (`world_save.go`).

**3. Scout registration + worker best-site pick.**
- Register: at the scout's Think, `hits := FindNearbyFood(state, pos, smallRadius, carrionAttractions)` (O(local) on the existing `ItemsByChunk` index). For each hit in sorted order, `registerCarrionSite(nest, cellX, cellY, density)` → add/refresh a `CarrionSite` (strength += density, clamped); if `len(Sites) > maxColonySites`, evict the lowest-strength (lowest-cell-key tiebreak). Workers dining at a site also refresh it (keeps a live site warm).
- Best-site pick (worker, deterministic): `bestKnownSite(nest, workerPos)` = argmax over sorted `Sites` of `Strength / (1 + dist)` (nearest×strongest), tiebreak lowest `"gx,gy"` key. No RNG in the pick → fully deterministic.
- Decay: fold into `processNests` (already every 30 ticks, `match.go:1177`) or a sibling `processColonyMemory`: each pass `Strength -= decayPerPass`; drop sites at `Strength <= 0` (the brood "source-gone sweep" precedent). This is the age-out.

**4. Carrion food gate → new shape alongside prey/nectar.**
`nestCanFeedNearby` (`nests.go:469`) currently branches empty-prey→nectar, else→prey. Ants also have an empty prey list, so add a **third shape** discriminated by a new species field (recommend an explicit `carrion_forager: true` on the species, or `predation.forage_kind: "carrion"` — explicit beats sniffing attraction strings). New helpers cloned from the nectar pair:
- `nestHasCarrionNearby(state, nest, species)` — scan `ItemsByChunk` for `FoodValue>0 && IsCarrion` within `HomeRange` of the nest (clone of `nestHasNectarNearby`, `nests.go:482`).
- `findNestSiteWithCarrion(...)` — daughter-founding site beside the richest carrion cluster (clone of `findNestSiteWithNectar`, `nests.go:438`).
Also patch `processNestFounding`'s `len(species.Predation.Prey) == 0` branch (`nests.go:338`) to route carrion foragers to `findNestSiteWithCarrion` instead of the nectar/box path.

**5. Queen → nest fixture, mini-boss is scripted/combat (out of sim scope).**
The colony's brood/hatch economy is the `ant_mound` `NestState` (verbatim wasp/bee reuse: `depositBrood`→`growSwarm`→`SWARM_REPRODUCED`). The (4,0) "Queen mini-boss" is a **combat encounter** on top — a high-HP stationary `ant_queen` bug/occupant killed via `BUG_REMOVED`/occupant-break, not a foraging swarm. Recommend keeping it entirely out of the species-sim PR and flagging it for the owner as combat/zone-content work.
