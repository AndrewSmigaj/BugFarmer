# ANT & colony-adjacent machinery — mapping report

**Bottom line:** There is **no ant species in the simulation** yet. Ants exist only as (a) sprite/data stubs in `bugs.json`, (b) one breakable world occupant (`ant_mound`) and a decoration placeable (`ant_eggs`), and (c) an extensive **design/brainstorm** corpus. Everything an ant colony would need — nest founding, brood/hatch, forager provisioning, carrion food registry, orphan-degradation, per-zone isolated sims with edge crossing — **already exists and is species-generic**, built for wasps and bees. Colony-memory / ACO-trails are a **design lens only**, not implemented anywhere in code.

## 3. `nakama/modules/world/` Go code — the NEST system ants would reuse

**"ant"/"colony" in code:** `grep` for `ant` finds only the word "colony" in comments/tests describing bee/wasp nests (e.g. `bee_test.go`, `nests.go`, `handlers_hive.go`). **No ant-specific code exists.** No `ColonyMemory`, `pheromone`, `TrailState`, or `aco` symbol exists in `nakama/modules/` (verified — zero hits).

### The NEST system — `nakama/modules/world/nests.go` (+ `nakama/modules/entities/nest.go`)

This is the species-generic machinery (author's comment, `nests.go:31`: *"NestState is deliberately species-generic (bees later…)"*). An ant colony would slot in as another `nest_occupant` species.

**`NestState` struct** (`entities/nest.go:12`): `GridX,GridY`, `EntityID` (occupant type), `SpeciesID`, `Brood int` (banked deposits, clamped at cap), `ResidentSwarmID`, `RehatchAtTick`, `Honey float32` (bee yield — display-only), `SmokedUntilTick`, `Founded bool`.

**Nest tuning constants** (`entities/nest.go:37`): `NestBroodCap 9`, `NestHatchCost 3`, `NestHatchCount 3`, `NestRehatchDelay 1200` (2 min), `NestRecoveryDelay 3000` (5 min), `NestFoundingSize 4`, `NestDefendRadius 5`, `NestDefendTicks 300`, `NestDepositRange 2.0`, `NestHomingTimeout 600` (a homing trip >60s drops its brood).

**Lifecycle functions in `nests.go`:**
- `speciesForNestOccupant` (`:37`) — maps an occupant id → the species whose `NestOccupant`/`NestOccupantsExtra` it is; bool flags a player-placed box (registers dormant).
- `initNestsInChunk` (`:58`) — on chunk load, scans occupant cells and registers nests (the fruit-tree "comes alive when a player approaches" pattern; no persistence).
- `registerNestAt` (`:89`) / `nestSpawnResident` (`:105`) — mint the resident patrol, **population-cap aware** (partial founding at the cap).
- `processNests` (`:143`, every 30 ticks) — occupant-gone sweep + **brood-drain re-hatch**: dead resident with banked brood re-staffs after `NestRehatchDelay`; **brood-exhausted → food-gated re-found** via `nestCanFeedNearby`.
- **`depositBrood`** (`:217`) — sated forager arrives home → `+1 brood` (clamped), honey (bees only, gated on `world.hive`), and the hatch check (consume `NestHatchCost` → `growSwarm` by `NestHatchCount`, cap-aware).
- **`processNestFounding`** (`:294`, called from `match.go:1180`) — a **thriving** colony (saturated patrol + full brood bank, under `MaxNests`, with population headroom) splits a daughter nest. **Branches on prey-list shape:** empty-prey (bee/ant-forager) → prefer an empty placeable box (`findClaimableBox`) else found beside a rich `ForagePool` (`findNestSiteWithNectar`); non-empty prey (wasp) → found beside a prey cluster (`findNestSiteWithPrey`). All deterministic (sorted iteration, distance tiebreaks).
- `nestCanFeedNearby`/`nestHasNectarNearby`/`nestHasPreyNearby` (`:469`–`:531`) — the **species-shape-aware food gate** (empty prey → needs a live flower `ForagePool`; else needs live prey in `HomeRange`). This is exactly where an "ant forages carrion" gate would hook.
- `onNestOccupantRemoved`/`orphanNestResident` (`:258`) — **graceful degradation**: destroyed nest orphans its resident (never breeds again, tethers to last `HomePos`, still hunts/stings).
- `recallNestDefenders` (`:598`) — aggro-on-damage → resident goes `"defending"`.

### Forager provisioning / "carry load home" — `nakama/modules/world/predation.go`

The `predationThink` priority chain (order: flee > defending > **homing/PROVISION** > feed-pause > nectar-forage > individual-carrion > hunt) drives the resident:
- **PROVISION/homing** (`predation.go:169`–`202`): when `Satiation >= predatorFullSatiation` and it has a live nest → `Phase="homing"`, `CarryingBrood=true`; on arriving within `NestDepositRange` it calls `depositBrood`, then `Satiation = p.DepositSatiation` and rests. Timeout drops the load (`CarryingBrood=false`).
- **NECTAR FORAGER special-case** (`predation.go:224`): *"a NEST species with an EMPTY prey list never hunts… declines ownership so the SHARED forage block dines on flower nectar; satiation climbs to full and the PROVISION block carries the load home."* **This is the precise template for "ant forager grazes carrion → carries brood home."** An ant forager = empty-prey nest species whose `feeding` attraction is `dead_*` items instead of flowers.
- `SwarmState` carry/phase fields (`entities/swarm.go:89`): `NestKey`, `CarryingBrood bool`, `HomingStartTick`, `DefendUntilTick`, `DefendTargetID`. Phase strings for nest species: `"feeding"` (hunt/graze), `"homing"`, `"defending"`.

Species-level pacing knobs are `deposit_satiation`, `hunt_satiation_threshold`, `feed_per_kill` (`PredationConfig`, §1).

### Carrion collection & the food registry ("pick up ground item / carry home")

There is **no literal pickup-and-carry-item mechanic**; foraging is *proximity dining* + brood-carry. Carrion is modeled as a **deterministic food registry** driven by ledger events:
- Any item with `food_value > 0` (`EntityDef.FoodValue`, `entities.go:68`) becomes edible ground food. `dead_fly/butterfly/wasp/centipede/millipede/beetle` all have `food_value: 10`, `dead_bee: 8` (`items.json:1076`+).
- Registry events `ITEM_ROTTED` (spawn) / `FOOD_CONSUMED` (expiry/level change) — `messages.go:884`; `AddFoodEvent` calls in `handlers_combat.go:267/365`, `handlers_farming.go`, `match.go:1767`.
- A predator's kill spawns a `dead_<prey>` drop (`carcass_item`) which enters this registry → detritivores (beetle_carrion, millipede) find it via `FindNearbyFood` and dine. The swarm caches a food target: `SwarmState.TargetFoodID/X/Y/Depletable` (`swarm.go:56`). The lens note *"Ants compete with detritivores for carrion"* (`lenses.md:101`) refers to competing over exactly this registry.

`deposit_satiation`, `feed_per_kill`, and the food registry are the three levers the report asked about — all present and species-generic.

## 5. Cross-zone — zones are ISOLATED per-match sims; only players cross, at edges

**Each zone is its own Nakama match with its own bug sim. No sim state crosses zones.** A bug cannot walk from one zone to another today.

- Zone connectivity is a per-zone **`Neighbors map[string]string`** (`zone.go:118`): edge direction → neighbor `zoneID`. Doc: *"Walking off an edge with a neighbor hidden-swaps into it (see CrossZoneController). Absent/'' = a hard edge. +Y = north."*
- **Client-driven crossing** — `BugFarmerClient/Assets/Scripts/Player/CrossZoneController.cs`: when the local player reaches within 2 cells of an edge that has a neighbor, it fades out, **`LeaveWorld()` (tears down match A) → `EnterWorld(neighborZone, char, entryX, entryY)` (joins match B)**, and places the player at the matching opposite edge (arrival insets `Lo=4`/`Hi=251`). Edges without a neighbor are a soft wall (clamp).
- **Server entry-override** — `match.go:395`: join metadata `entry_x/entry_y` (anti-forge: must be within 4 cells of an edge) overrides the character save's spawn (`match.go:493`). `state.go:97` holds the cross-zone entry position. Neighbors are surfaced to the client in the `world_enter` RPC response (`rpc/world.go:396`).
