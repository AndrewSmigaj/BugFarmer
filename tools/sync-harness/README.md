# sync-harness

A headless Bug Farmer client for testing the frontier-gated sync system **without Unity**.

It reuses the real Nakama .NET SDK (`NakamaClient`, the same client the Unity package wraps —
protocol-compatible with the server), so it speaks the exact wire protocol. It is a **protocol
observer**, not a reimplementation of the client sync state machine: it joins a world, records
every incoming match message, tracks the tick frontier, and flags any reception gap. Its question
is narrow and decisive — *does the server keep delivering ticks to a present client?*

Because a console app runs the SDK without Unity's `useMainThread` main-thread pump, the harness
**isolates the Unity-specific layer**: if the harness runs clean while the Unity client freezes,
the bug is on the Unity side, not the server/protocol.

## Run (host)

Requires the .NET 8 SDK (`~/.dotnet/dotnet` here; or any `dotnet` on PATH) and the server up
(`docker compose up -d`).

```bash
cd tools/sync-harness
dotnet run -- --zone sim_test --duration 150        # lone authority on the minimal test zone
dotnet run -- --zone village_21 --duration 70       # full production load (scale-up check)
```

Flags: `--host` (default 127.0.0.1), `--port` (7350), `--key` (defaultkey), `--zone` (sim_test),
`--duration` seconds (150), `--tag` (player label). Exit code 0 = ticks advanced with no gap.

## What it reports

Per-5s progress (`authTick`, `lastSeq`, `recv`), and on any >2s silence:
`RECEPTION GAP gap=Xs lastAuthTick=.. recvCount=.. connected=..` — the freeze signature. The
summary prints `maxAuthTick`, `recvCount`, `gaps`, and a per-opcode tally
(op78 = ZoneTickBroadcast/tick, op76 = ZoneAuthority, op71 = influence, op72/73 = late-join).

## Test worlds

`sim_test` (and any test zone) is generated by `tools/make_test_zone.py` — small, deterministic,
`static` (no spawn/merge/split). Scale toward production load with `--initial N` there, then point
the harness at it. See that script's `--help`.

## Finding (2026-06-04)

Both `sim_test` (1 swarm) and `village_21` (~40 swarms, full dynamics) ran hundreds of ticks with
**zero reception gaps** — the server delivers ticks reliably under all loads. The lone-authority
freeze at ~tick 94 is therefore **Unity-client-side** (the main-thread message pump), not the
server. Next: instrument `SwarmManager` and confirm on a Play run.
